1. Version Control

Definition: Version Control is a system that tracks changes made to files over time.

It allows you to:

* Track changes in your project.
* See who made changes.
* Restore an older version if something goes wrong.
* Work with other developers without losing each other’s work.

Example:

Imagine you’re building a website.

* Monday: You create the homepage.
* Tuesday: You add a login page.
* Wednesday: You change the homepage design.
* Thursday: You accidentally delete some important code.

With Version Control, you can go back to an earlier version of your project.

Think of it as a history book for your code.

2. Repository (Repo)

Definition: A Repository is a storage location where your project’s files and their version history are kept.

It contains:

* Your project files.
* Folders.
* Code.
* Commit history.
* Branches.

Example:

You create a project called MyWebsite.

You create a Git repository for it.

That repository keeps track of everything related to your project.

Think of a repository as a project folder with a tracking system.

3. Commit

Definition: A Commit is a saved snapshot of the changes you’ve made to your project.

Whenever you complete a meaningful task, you can commit your changes.

Example:

You’re building a website.

1. You create the homepage.
2. You save your changes with a commit.
3. You add a login page.
4. You create another commit.

Each commit records a point in your project’s history.

Example commit message:
Added homepage

Think of a commit as saving a checkpoint in a game. If something goes wrong, you can return to an earlier checkpoint.

4. Branch

Definition: A Branch is a separate line of development that allows you to work on something without affecting the main version of your project.

Example:

You’re working on a website with a main branch called main.

You want to add a login page.

Instead of making changes directly to the main project, you create another branch called login-page.

Now you can:

* Work on the login page.
* Test it.
* Fix errors.
* Make changes without affecting the main branch.

Think of a branch as creating a separate workspace for a new feature.

5. Merge

Definition: Merge is the process of combining changes from one branch into another branch.

Example:

You have two branches:

* main — Your original website.
* login-page — Your newly developed login page.

After completing and testing the login page, you merge login-page into main.

Now the main branch contains the login page.

Think of merging as bringing two separate pieces of work together.
